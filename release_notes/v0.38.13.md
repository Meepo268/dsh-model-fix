# 0.38.13

## 新增：卡片末尾「检查更新」

版本号旁边多了一枚按钮，点一下才查一次 GitHub 上的最新 Release（`api.github.com` 的 `releases/latest`；匿名限 60 次/小时，所以不轮询、也不随卡片挂载自检）：

- 有新版：变「vX 可用」+「复制安装地址」。复制的是**构建产物 tarball**、地址钉在 tag 上（`releases/download/vX/dsh-model-fix.tgz`），直接粘进「设置 → 插件 → 添加插件」即可；旁边那枚「vX 可用」同时开 Release 页。
- 已是最新：显示「已是最新」，4 秒后复原。
- 查不到（离线 / 限流 / webview 拦了请求）：显示「检查失败」，点一下直接开 Releases 页挑版本——检查更新坏掉不能连累卡片其它部分。
- 不代装、不写 profile、不改 `package.json`：这一步只负责告诉你「有没有新版、地址是什么」。

## 保存供应商后不必再点「刷新声明」

宿主保存自定义供应商是两次写入：设置文档先落盘（这一下触发插件填充），密钥随后才进凭据库。插件在设置事件里就开抓，那一刻 `credentials.resolve` 还拿不到密钥，只能发匿名请求——网关回 401，落进 1 分钟失败缓存。于是保存后看到的是 models.dev 目录值，点一次「刷新声明」才变上游。

现在订阅 `credentials/record-updated` / `credentials/reference-updated`：密钥入库那一刻，等当前在途抓取结算 → 只放掉失败过的地址（成功的 6 小时声明不动）→ 再跑一轮保守填充。

- 升级仍走「允许更新」+ 指纹闸门：只把插件自己写下的目录值改成上游声明，手填值不受影响；`allowUpdate` 全关时行为不变（那是既有的保守语义）。
- 只重抓失败过的地址，其余复用缓存；没有失败地址时整条短路，重复事件不会叠加。
- 打开排查日志会多一行：`凭据入库，放掉 N 个失败地址后重抓上游声明`。
