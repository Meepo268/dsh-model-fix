补齐上游声明的字段并集：magpie 这类网关自报的档位与图片模态此前一个都不认，现在能认，顺带把 OpenRouter / LiteLLM / LM Studio 几套血统的漏项一起补上。

### 问题修复

- 修复 magpie 网关的模型参数填不上：magpie 的 `GET /v1/models` 用 `reasoning_levels` + `supported_reasoning_levels[].effort` 报档位、用 `modalities.input` 报图片，这两个键此前都不认，于是档位与模态两维全程沉默（实测其 9 个模型：修复前 0 条带档位、0 条带图片；修复后 9/9 两维俱全）。
- 修复 `supported_parameters` 是**字符串数组**（OpenRouter 血统：`["tools","reasoning"]`）时被当成对象读取的问题：现在按形状判否跳过，不会因类型不符抛错，也不会误读成档位。

### 功能增强

- 声明侧四维改为**候选表**（顺序即优先级，见 `docs/decisions-config.md`「参数来源」）：
  - 档位：`reasoning_options[].values` → `reasoning_levels[]` → `supported_reasoning_levels[].effort` → `reasoning_supported_efforts` → `supported_parameters.reasoning_efforts` → `capabilities.reasoning_efforts`（**并集**：多源合并去重，顺序即写盘键序）
  - 上下文：`context_window` → `context_length` → `max_input_tokens` → `limit.context` → `top_provider.context_length` → `max_context_length`（LM Studio 原生口）
  - 输出上限：`max_output_tokens` → `max_completion_tokens` → `limit.output` → `top_provider.max_completion_tokens` → `max_tokens`（**先到先得**）
  - 模态：`input_modalities` / `architecture.input_modalities` / `supports_images` / `modalities.input` / `capabilities.vision`（任一为真即真）
- `max_tokens` 从第 3 位挪到末位：有的网关用它指输出上限、有的指上下文长度，语义不稳，只在该模型别无他据时才采用（`limit.output` 等 models.dev 形状现在优先）。
- `reasoning_levels` 的字符串形（`["none","low","high"]`）、对象形（`[{effort:"high"}]`）与混合形（`[{effort:"low"}, "high"]`）都能读，混合形按原序展开；`supported_reasoning_levels` 取每项的 `effort`。
