# 0.38.15

## 适配宿主 0.2.3-alpha.2：RPC 端点不再 400

宿主从 0.2.2-rc.1 升上来之后，「参数来源」弹窗直接报

```txt
取数或保存失败：transport failure for /tikaflow-model-fix/sources: HTTP 400
```

而且是所有走本插件 channel 的端点一起废（保存、刷新声明、抓目录、来源读写、语言上报），不只是 sources。

### 原因

宿主 `0.2.3-alpha.2` 删掉了 `HostConnectionService.requestRejection()`，而插件每个 channel 请求都先调它做信任围栏（非受信来源 403、浏览器会话未认证 401）。方法没了 → `TypeError: connection.requestRejection is not a function` → 路由 handler 抛错 → 宿主 webserver 的兜底 catch 回 400 → 客户端把它显示成上面那句 `transport failure`。

### 改法

围栏改由插件自己合成（`src/rpc.ts` 的 `fenceOf`），按宿主能力挑一条路：

- `connection.admit(request)`（0.2.3-alpha 起）：返回 `{ peer }` 放行、`{ rejection: 401 | 403 | 503 }` 拒答，判定内容与旧的 `requestRejection` 完全一致（同一份 `isTrustedApiRequest` + 会话认证）；
- `connection.requestRejection(request)`（旧宿主）：原样照旧；
- 两样都没有：退回「宿主路由 auth 传进来的 `peer` 存在才放行」，不会出现无认证可写的端点。

`admit` 抛错按 403 处理，围栏 fail closed，异常不会再冒到宿主兜底变成 400。`createChannelRoute` 因此只接受一个 `(request) => number | undefined` 的围栏函数，与宿主版本无关。

### 一并说明

- 路由仍不显式写 `auth`：宿主对 `webServer.register` 路由的默认策略就是 `required`，而 0.1.x 的 `WebRoute` 类型里还没有这个字段，省略它两边都成立。
- 进度流（验证模型、探测档位）走的是 `connection.fetch.register`，该 API 没变，不受影响。
- 新增 9 条单测：`fenceOf` 对 `admit` 放行/401/503/抛错、`requestRejection` 放行/拒答、两者并存时优先 `admit`、两代 API 都没有时返回 `undefined`，以及路由层 503 与「围栏放行」两条路径。
