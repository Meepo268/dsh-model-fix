# v0.38.16

## 修复：DSH 0.2.3-alpha 起「参数来源」弹层报 `transport failure … HTTP 403`

上一版把信任围栏从 `requestRejection` 换成了 `admit`，请求不再抛错，但落到了 403。根因是浏览器半到 Node 半
这条通道一直是插件**自己**在 `webServer` 上注册的前缀路由，围栏要靠宿主内部 API 复刻；宿主每改一次这套 API，
插件就得跟着改一次（0.2.3-alpha 已经改了两回）。

这一版换掉这条路：通道改挂宿主的 `connection.rpc` 注册表（`handle(channel, handler)`），信封解析、方法/类型
校验、Host/Origin 围栏与浏览器会话认证全部由宿主完成——和官方 `/api` 通道走的是同一条路，宿主以后再改围栏
也不需要插件跟着改。

- `src/rpc.ts`：新增 `registerHostChannel(connection, channel, handler)`，优先 `connection.rpc.handle`；
  取不到（旧宿主）或注册当场抛错时返回 `undefined`，退回原来的 `webServer` 前缀路由 + `fenceOf` 围栏，
  0.1.x/0.2.x 两代宿主都能装上。
- 进度流（验证模型 / 探测档位）不变，仍走 `connection.fetch` 的 exact 路由——它本来就由宿主代管围栏与认证。

装上后在「设置 → 模型」的供应商卡片里打开「参数来源」应立即列出模型，不必再点「刷新数据」。
