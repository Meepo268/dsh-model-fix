# 目录职责与数据流

`AGENTS.md` 只留四条目录要点与索引，正文在此；仅供开发查阅，不进 `files`。

技术栈：Node.js（ESM）+ `@deepseek-ai/cordis`；tsdown 双配置构建到 `lib/`（Node 半 + 浏览器半，clean 只由 Node 半承担）；TS 严格模式，产物不带 sourcemap；ESLint 10 扁平配置。

## 目录职责（只写非显而易见的部分）

| 路径 | 职责 |
| --- | --- |
| `src/index.ts` | Node 半入口：`Config`（宿主经 `entry.fiber.runtime.Config` 取用）+ 单一 `apply` 编排体（备份 → 配置源与段变更接线 → **installSubagentFollowParent** → installRpc → 启动链） |
| `src/subagent.ts` | 子智能体推理级别的**请求期改写面**（唯一的对外挂钩是宿主 `agent/request` 瀑布）：三个宿主服务（`agents` / `sessionProjections` / `subagentModelSelection`）经 `ctx.inject` 子 fiber 注入（全就绪才注册监听，缺席 PENDING 静默），`agent/request` 监听 `{ prepend: true }` 钉最外层即覆盖全部 Agent（scope 过滤机制与宿主注入面详见 `host-api.md`「agent/request」节）；跟随判定与取路由口径见 `decisions.md`「子智能体」。`resolveFollow` 从 fiber 捕获的 `agents` / `projections` 服务取父 Agent 与父会话待生效的模型选择，不碰配置与目录，判定纯靠入参；取路由顺序（父的待生效选择 → 最近一次请求头 → 父 options）见 `decisions.md`「子智能体」 |
| `src/self-tune.ts` | 推理档位自调的**工具注入面**（对外挂钩是宿主 `tools` / `systemPrompt` / `sessionController` / `sessionProjections` 四个服务）：按 `userExperience.selfTune` 开关装/卸注入面——两枚工具（`query_reasoning_efforts` 查当前模型可用档位、`set_reasoning_effort` 经 `sessionController.selectModel` 设档，与 UI 手选同一条链路）与一段静态系统提示词（order 3200）。查询走 `llm.resolveModelInfo`（全量提供方，不限于本插件填充的 llm-pi-ai）；档位值一律取 `efforts[].id` 实际值、不设 `'default'` 哨兵；当前路由的回落链（投影 pending/lastUsed → 请求头 → Agent options）与 `src/subagent.ts` 同源。四个宿主服务**均契约复制、不引包类型**（理由同 `src/subagent.ts` 裁决），经 `ctx.inject` 子 fiber 门控（全就绪才激活、缺席 PENDING 静默）；插件零状态（档位状态全在宿主），开关切换只是装/卸注入面，HMR 无损 |
| `src/shared/` | 跨半共享层（零 Node 依赖 / 零 schemastery / 零非基线 `@deepseek-ai/*`）：常量、异常文案取法 `errorText`（两个半都要）、`isPlainObject`/`providersOf`、当前版本配置的解析与物化与各组行键表、**验证与探测式填充共用**的探测契约（明细 / 汇报 / 进度帧 / 可用与不支持档位明细 / 写回统计，浏览器半须据此解析回传，禁反向 import Node 半）。**推理级别记忆查表 `lookupEffort` 留在浏览器半的 `effort.ts`**（查表为何归浏览器半见 `decisions.md`「推理级别记忆」） |
| `src/config.ts` `src/migrate.ts` `src/upgrade.ts` `src/catalog.ts` `src/lookup.ts` `src/compat.ts` | 配置解析与配置源 / 当前版本侧的启动迁移、旧快照清理与自愈（`migrateConfig`；选迁移源时才调 `upgradeConfig`）/ **冻结的升级台阶链** `upgradeTo4..8`（历史形态的堆栈，**刻意不引用 `CONFIG_VERSION` 或当前版本默认值**，新增台阶只改这里）/ 缓存读写与目录拍平 / id 匹配与档位转换 / 路由 compat 纯写入计划 |
| `src/fix.ts` | 填充与写回：两层遍历是**纯计划函数 `planFill`**（零 ctx，出 `FillPlan`：模型参数 op、路由 compat op），`fix` 只做编排（`force` 供强制更新单次绕过；读最新段 → 出计划 → 写回 `llm-pi-ai` 一段 → 冲突重试时重读）；模型参数与路由 compat 同批提交；`excludes` 命中者在 provider 循环入口整条跳过。`efforts` 不在此处理（记忆存取在浏览器半、清理在 Node 半，见本表 `memory-listener.ts` / `memory.ts` 行） |
| `src/memory.ts` | 推理级别记忆的**失效清理**（Node 半唯一碰记忆的地方）：`collectLiveModels` 取存活清单（`ctx.llm.listProviders()` 同步取全量路由，**只对有记忆条目的 provider** 调 `listModels`；某 provider 读失败标成 `null`＝未知而非不存在；整体退化读返回 `null`＝本轮不剪）→ 纯函数 `planPruneMemory`（缺席即删除、段删空则折叠、改入参不共享引用）→ 经 `descriptorOf` + `queueTask` 只写自有段的 `efforts` 一个键。`updateMemory` 是串行化入口：在途时来的触发只置 `pending`、结束后补跑一轮；触发面是 `llm/adapters-updated`、llm-pi-ai 段变更后与启动首轮 |
| `src/empty.ts` | 空壳字段的唯一判据 `stripEmptyFields`：`reasoningEfforts` / `input` / `compat` 的空形态一律等同「未声明」，**五条写回路径（`fix` 填充、`reset`、`restore`、`prune` 剔除、`fill` 探测式填充的预声明与收敛）统一过它**，不在各模块另写一份；无空壳时返回原引用，调用方以引用相等判「无需重建」。注意它只清**空形态**：把某个键整个删掉得由调用方显式 `delete` |
| `src/reset.ts` `src/restore.ts` `src/guard.ts` `src/host.ts` `src/section.ts` `src/writeback.ts` `src/prune.ts` | 重置推理级别（仅剔除 `reasoningEfforts`，配置段零写入）/ 启动备份捕获与交集恢复 / 事件流守卫（写回期间短路整条事件链）/ **全部 settings 写回必经的 `queueTask`**（hmr 执行上下文经 `src/index.ts` 的子 fiber 注入，注入落地前有界等待一次、超时才降级为裸 `task()`，见 `decisions.md`「写回端点」）/ **settings 节读取的唯一收口**（`descriptorOf` 取描述、`sectionOf` 把 `user` 收窄成整段、`ownSection` 读自有段；读不到一律返回 `undefined`，「显式失败还是静默早退」留给调用方决定，不在读取层替它选）/ **写回 `llm-pi-ai` 段的统一外壳**（读最新段 → 纯函数出计划 → 经 `queueTask` 写回 → `SETTINGS_CONFLICT` 限次重试；各端点只给「段不可读怎么办、计划怎么算、日志报什么」，文案一字不改。`guardedWritebackApi` 自带守卫、给守卫只覆盖本轮的端点用，`writebackApi` 给守卫持有整轮的探测式填充。`fix` 与探测兜底回退**刻意留在原处不套壳**，理由见该文件头）/ 剔除验证明细中**明确不支持**的档位（写入前判空壳、`excludes` 跳过、幂等） |
| `src/probe-verdict.ts` | **验证与探测式填充共用的判定层**（零 ctx、不触网的纯函数，判定口径与执行、汇报分开才便于逐条钉住）：失败**只按** `LlmFailure` 的 `code` 分类（限流与超时单列瞬态，只否定这一次）、`isEffortRejection`（`INVALID_REQUEST`，判「档位不支持」的第一条件）、**两级短路的判据**（只有一条：**能断定后续必然失败才短**。`providerBlockReason`：端点不通 / 凭据无效 / **本组首个请求超时**；`shouldSkipModelTail`：档位请求上只有额度耗尽够格；`shouldSkipModelTailAfterBaseline`：基线不带档位、失败天生与档位无关，故多认「被厂商确定性拒绝」）、`sameModelTail`（该模型档位尾还剩几条，供进度帧记 `skipped`） |
| `src/probe-plan.ts` | **验证与探测式填充共用的计划层**（判定归 `probe-verdict.ts`、执行归 `probe-engine.ts`）：把浏览器半发来的未信任载荷校验并展开成待跑清单（`planProbes`：按模型逐档展开，清单里只有**被验对象**，基线探测不进计划）、两条硬闸配额 `ProbeLimits`（真正发出的请求数含基线 + 计划模型数，超出即拒绝而非静默截断；两个功能各给一份 `VERIFY_LIMITS`/`PROBE_LIMITS`，为何是硬闸、各是多少见 `decisions.md`「验证」「探测式填充」）、按 provider 分组（`groupProbesByProvider`，分组即「每 provider 单并发」的结构保证）、`planProbeGroups`（校验失败按各功能自己的文案抛出，故与执行拆两步：探测式填充的 `done` 帧要含收敛写回结果） |
| `src/probe-report.ts` | **验证与探测式填充共用的汇报层**（判定归 `probe-verdict.ts`、计划归 `probe-plan.ts`、执行归 `probe-engine.ts`）：`reportProvider`（单组结论折一份汇报：可用模型按「提供方 / 模型」去重、档位不可用单列、**可达与凭据取自全程**含基线探测而非首个，且只认能否否定整个提供方的失败，额度耗尽两者都不翻）与 `summarizeProviders`（全局求和并同源产出 `usableEfforts` / `unsupportedEfforts` 两种明确状态的档位明细，浏览器半不自己重筛）。纯函数、零 ctx、不触网 |
| `src/probe-engine.ts` | **验证与探测式填充共用的执行引擎**（判定归 `probe-verdict.ts`、计划归 `probe-plan.ts`、汇报归 `probe-report.ts`）：`probeOnce`（只认 `block-start`、30s 超时、`AbortSignal.any` 合成外部中止，失败分类转交判定层）、`runProbeGroups`（跨 provider ≤5 路并发与进度帧；已中止即不再开新组，从未开跑的组保持 `undefined` 并被排除在汇报之外）、`finishRun`（中止不发 `done`）。两个功能只差注入的 `runGroup` |
| `src/verify.ts` | 「验证模型」执行器，只留验证独有的一段：`needTest` 为真的模型现发一次不带 `reasoningEffort` 的**基线探测**（不进计划/明细/统计，跑通不发帧，不通则发一条模型级记录并参与 `reachable`/`keyValid` 记账），以及两级短路（判据全在 `probe-verdict.ts`；为何要有基线与两级短路、档位开关关闭时不发档位参数见 `decisions.md`「验证」） |
| `src/probe.ts` `src/fill.ts` `src/probe-backup.ts` | 「探测式填充」执行器、两次写回与崩溃兜底：`probeAndFill(ctx, llm, payload, options)` = 校验三个开关（忽略排除 / 剔除不支持 / 自动写入）→ 展开至多七档计划（off 仅已声明时才探测） → **兜底备份**（`probe-backup` 把整段 providers deflate+base64 存进自有段顶层键 `probeBackup`，与 `version-N` 同级、故不进快照也**不动 `CONFIG_VERSION`**；存不下即整轮中止，没有退路就不动用户配置）→ **预声明**（`fill.ts` 按 `EFFORT_LEVELS` 排序写进配置并返回预声明之前的原有档位表）→ 逐档探测 → **收敛结论**（口径见 [`decisions.md`](decisions.md)「探测式填充」；只算不写——「自动写入」关闭时写回端走整轮还原，统计为「可补全」假设值）→ 清备份 → 统计随终帧回传（`VerifySummary.fill` 一律携带，开启即已写入的补全、关闭即假设值）。守卫**持有整轮**；两次写回共用 `planEffortApply`，`modelOps` 按当前值比对、增删统计按传入基线（预声明之前那份）比对 |
| `src/rpc.ts` `src/rpc-route.ts` `src/refresh.ts` | 四个 channel RPC 写回端点（以守卫互斥、验证只读不参与）+ **两条进度流**（`connection.fetch` 的 exact 路由，SSE 分帧，客户端断开即中止执行）：两者共用 `progressStreamFetch`，探测那条因一轮之内要写两次配置而**入口先查守卫**（已开回 409 + 中文文案）/ 保鲜刷新 |
| `src/official-filter.ts` | 「隐藏官方API」（只读，零配置写入）：`installOfficialFilter(ctx)` 在 `ctx.llm` 实例上以自有属性遮蔽原型 `listModels`——命中名单（`HIDDEN_OFFICIAL_PROVIDERS`，当前只有 `deepseek-official`）且判定未配置密钥时返回空清单，宿主 `buildModelCatalog` 随即把模型数为 0 的组从 UI 目录里滤掉；否则直通原方法。判定口径同「设置→模型」小红点（configurable-provider 目录取 settingsNs/settingsPath → 段上 `apiKeyEnv` → `credentials.describe().configured`），每次调用现算，**不缓存、不挂任何事件**；凭据服务缺席 / 目录无该提供方 / 引用名非法 / 读取抛错四类情况一律放行不隐藏。名单里不放 `deepseek-account`（该段无 `apiKeyEnv`，判定会错配到 `DEEPSEEK_API_KEY` 而误隐藏可用的账号组；且宿主自 `0.1.7-rc.2` 起已自带登录门） |
| `src/client/index.tsx` | 浏览器半入口：四个卡片刻位注册（共用一份 `cardProps` 展开）、词典注册、调用面接线、scope 释放、记忆监听子 fiber（本体见 `memory-listener.ts`）、界面语言上报（本体见 `effort-name.ts`） |
| `src/client/memory-listener.ts` | 浏览器半的推理级别记忆监听（`applyEffortMemoryListener`，与卡片零共享状态）：订阅会话 `modelSelection` 投影，按 `classifyTransition` 翻译成「换模型恢复记忆」与「换级别存回记忆 + `defaultHigh` 自动设置」，另按 `rememberEfforts` 写记忆、按 `defaultHigh` 自动设级别（两者与卡片同属一条监听链）。**只管存取，不管整理**——失效清理由 Node 半的 `memory.ts` 按全量模型列表执行。与卡片分居两处是因为一个管用户在设置页看见的配置、一个管所有活着会话的后台行为 |
| `src/effort-name.ts` | 档位名本地化（`installEffortNameLocale`，Node 半只读支线）：`efforts[].name` 只在 `ctx.llm.resolveModelInfo` 的返回里出现（目录、UI 菜单、subagent list-models 工具全取它），故在 `ctx.llm` 实例上以自有属性遮蔽该方法，命中「开关开 + 中文界面」即替换 `efforts[].name`（`localizeEfforts` 开着时再看 `showOriginalEfforts` 决定是否在中文名后追加 ` · 原档位名`），`id` 与 `defaultEffort` 一律不动（纯函数 `localizeEffortNames` 可单测；词表键取宿主口径的首字母大写形式，键集由共享层 `EFFORT_LEVELS` 约束）。语言三路判定：settings 文档 `locale.preference` → 浏览器上报（`reportLocale`，rpc 端点 `reportLocale` 落点）→ 回退 `en`；判定每次调用现算，不缓存、不挂事件；卸载只清活状态位、遮蔽层退化直通 |
| `src/client/rpc-carrier.ts` | 浏览器半调 Node 半的**唯一出口**（`makeRpcCarrier`）：四个写回端点的 channel RPC 与**两条进度流的读流**（共用 `streamSummary`，非 2xx 取响应体文案作报错）。`RpcCarrier` 是卡片调用面的单一来源（`CardProps extends RpcCarrier`），故卡片只管状态与编排、不认 Connection |
| `src/client/card-styles.ts` | 卡片的样式层（**全部样式数值的唯一出处**）：`STYLE_TEXT` 内嵌样式表（类名 `dsh-mf-` 前缀防撞、取值逐条照官方同类组件）、`ensureStyles` 幂等注入（带 `data-plugin` 标记供宿主 HMR 认领）、说明气泡宽度上限 `TIP_MAX_WIDTH` |
| `src/client/tile.tsx` | 卡片的瓦片层（五张瓦片的两种形态，顺序由 `TILE_ORDER` 单一分发）：`GroupTile` 布尔矩阵配置组瓦片（组开关 + 子开关行 + 行内说明气泡）、`ExcludesTile` 动态集合瓦片（手填 id、「N 命中」徽标常驻，输入文本与校验反馈是留在本地的纯 UI 暂态）。**瓦片只管自己的 summary 与展开体**，展开态 / 启用态 / 写回回调全由卡片经 props 传入，故不碰 Connection |

## 数据流骨架

段变更按 ns 分流为两条链：自有段「自愈 → 填充」、llm-pi-ai 段「填充 → 保鲜刷新」，入口先判事件流守卫。浏览器半：`configForms` → `makeScope` → 四席共用同一张卡 + 记忆监听子 fiber（**存取全在前端**、不经 `fix`）；记忆的**失效清理**是第三条支线（Node 半 `memory.ts`）：由 `llm/adapters-updated`、llm-pi-ai 段变更后与启动首轮触发，按 `ctx.llm` 的全量模型列表缺席即删除，只写自有段的 `efforts` 一个键。第三条链是**请求期**的（不经事件、不写配置）：宿主每次委派子智能体时 `agent/request` 瀑布 → `src/subagent.ts` 判「是子智能体吗 / `userExperience.followParent` 开着吗 / 宿主那条「允许为子智能体选模型」关着吗」，三条皆满足才把整条路由覆盖为父 Agent 下一次请求该用的路由（父会话待生效的模型选择优先于最近一次请求头；输出预算取更小者、父那份更大时只抬升差值的八成）并返回新配置，否则原样放行，宿主随即照常做适配器元数据校验。第四条链是**工具调用期**的（不经事件、自身零写入）：`userExperience.selfTune` 开启时 `src/self-tune.ts` 向宿主注入两枚工具与一段系统提示词，AI 调查询工具时按与子智能体同源的回落链（投影待生效选择 → 最近一次请求头 → Agent options）读当前路由，调设置工具走 `sessionController.selectModel`——与 UI 手选同一条链路，落 `model/selection` 事件、由记忆监听支线照常接住；档位不被支持时宿主校验抛 RemoteError 由工具原样透传给 AI，「先查后设」靠提示词软指引而非硬校验。

另有**模型目录过滤**这条只读支线（Node 半 `src/official-filter.ts`，无事件、零配置写入）：宿主生成 UI 模型目录时（`modelCatalog` 远程 → `buildModelCatalog`）逐 provider 调 `ctx.llm.listModels`，本插件在 `listModels` 上以实例自有属性遮一层，命中名单且未配置密钥即返回空清单，宿主随即把该组从目录里滤掉；判定每次调用现算（读实时配置 + `credentials.describe`），故开关翻转与密钥配置之后目录自动按新状态收敛，**插件侧不挂任何事件**。开关翻转写的是自有段（`settings/document-updated`），密钥存取走 `credentials/*-updated`，两者在宿主浏览器侧都由 `catalog.refresh()` 承接。**宿主自 `0.2.1-alpha.2` 起对 `deepseek-official` 自己做了同一件事**（`llm-deepseek-api-key` 的 `discoverModels` 未配密钥即返回 `[]`），故这条支线在新宿主上是冗余但无害的兜底（老宿主上仍是唯一手段）；`deepseek-account` 自 `0.1.7-rc.2` 起自带登录门、且其 profile 没有 `apiKeyEnv`，**不在名单内**（理由见 `docs/host-api.md`「已知漂移与观察项」）。

与它同一遮蔽面、同在 Node 半的还有**档位名本地化**（`src/effort-name.ts`）：`efforts[].name` 只在 `ctx.llm.resolveModelInfo` 的返回里出现，本插件在这层换一层，命中「`localizeEfforts` 开 + 中文界面」时把档位显示名换成中文（按 `showOriginalEfforts` 追加 ` · 原档位名`；`id` / `defaultEffort` 不动）。判定每次调用现算，同样不缓存、不挂事件；语言或开关变化在**下一次解析**时生效（UI 侧重开选择器即重取目录）。

两条诊断链路：

- **验证**（只读）：卡片弹层 → `verifyTargets` → 进度流端点（`fetch` 逐帧回调）→ `ctx.llm`。
- **探测式填充**（写回，是否落结论随「自动写入」开关）：卡片弹层（点开时冻结候选）→ `probeTargetsOf` → 探测进度流端点 → Node 半「兜底备份 → 预声明 → `ctx.llm` 逐档 → 收敛结论照算（自动写入关闭时写回端整轮还原、统计只算不写）→ 清备份」→ 终帧带统计 → 卡片把结论追加进记录区并留在窗内由用户自行关窗（自动写入开启时另落状态行，关闭时另报一行「可补全…未执行写入」）；全程持事件流守卫。崩在中途则由**启动链末尾**的回退收拾（`restoreProbeBackup` → 补一轮 `fix`）。
